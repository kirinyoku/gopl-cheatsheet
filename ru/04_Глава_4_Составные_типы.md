## 4.1. Массивы (Arrays)

Массив — это структура **фиксированной длины** из элементов одного типа. В Go массивы используются в основном как низкоуровневый фундамент для срезов.

### Особенности работы с массивами
* **Длина — часть типа**: `[3]int` и `[4]int` — два несовместимых типа. Нельзя присвоить один другому или передать не тот размер в функцию.
* **Передача по значению**: При передаче массива в функцию **копируется весь массив целиком**, а не ссылка. Чтобы избежать лишнего копирования, передают указатель `*[32]byte`.
* **Сравнение**: Массивы можно сравнивать через `==`, если их элементы сравниваемы.

```go
var a [3]int                  // [0, 0, 0] — заполнен нулевыми значениями
q := [3]int{1, 2, 3}          // явный размер
r := [...]int{1, 2, 3, 4}     // компилятор сам посчитает длину (4)

// Инициализация по индексам (остальные ячейки получат 0):
days := [...]string{1: "Пн", 2: "Вт", 7: "Вс"} // длина 8 (индексы 0..7)
```

## 4.2. Срезы (Slices)

Срез — это легковесный дескриптор, ссылающийся на непрерывный сегмент **базового массива**.

### Внутреннее устройство среза
Срез состоит ровно из 3 полей (24 байта на 64-битной платформе):
1. `ptr` — указатель на первый доступный элемент базового массива.
2. `len` — текущая длина среза (`len(s)`).
3. `cap` — ёмкость: расстояние от начала среза до конца базового массива (`cap(s)`).

```go
s := make([]int, len, cap) // выделяет массив и создает срез
```

```
Срез s: [ ptr | len | cap ]
           │
           ▼
Массив:  [ 0 | 1 | 2 | 3 | 4 | 5 | ... ]
         ├───────────┤
             len (текущие элементы)
         ├─────────────────────────────┤
                      cap (доступная емкость)
```

### Правила работы со срезами
* **Общий массив**: Несколько срезов могут указывать на один массив. Изменение элемента в одном срезе отразится на других.
* **Сравнение**: Срезы **нельзя сравнивать через `==`** (за исключением `s == nil`). Для байтовых срезов используют `bytes.Equal(a, b)`.

> [!TIP]
> Для проверки среза на пустоту всегда проверяйте `len(s) == 0`, а не `s == nil`, так как пустой срез `[]int{}` не равен `nil`, но его длина равна 0.

### Расширение срезов (`append`)
Функция `append` добавляет элементы в конец среза:
* Если `len < cap` $\to$ элемент записывается в свободную ячейку базового массива, `len` увеличивается.
* Если `len == cap` $\to$ выделяется **новый базовый массив большего размера**, старые элементы копируются, и возвращается новый срез.
* **Стратегия роста**: малые срезы растут примерно вдвое, но коэффициент плавно снижается до ~$1.25\times$ для больших (в книге — упрощённое «удвоение до 1000 элементов»; в рантайме формула менялась от версии к версии).

```go
s = append(s, 10)
s = append(s, 20, 30)
s = append(s, otherSlice...) // добавление среза через распаковку '...'
```

### Эффективные операции «на месте» (In-place)
```go
// 1. Стек (LIFO)
stack = append(stack, v)                // Push
top := stack[len(stack)-1]              // Peek
stack = stack[:len(stack)-1]            // Pop

// 2. Удаление i-го элемента с сохранением порядка
func remove(slice []int, i int) []int {
    copy(slice[i:], slice[i+1:])
    return slice[:len(slice)-1]
}

// 3. Быстрое удаление i-го элемента (без сохранения порядка, O(1))
func removeQuick(slice []int, i int) []int {
    slice[i] = slice[len(slice)-1]
    return slice[:len(slice)-1]
}
```

> [!NOTE]
> **Актуальность (Go 1.21+):** в стандартной библиотеке появился дженерик-пакет `slices` — самописные хелперы выше больше не нужны: `slices.Equal`, `slices.Clone`, `slices.Delete`, `slices.Insert`, `slices.Index`, `slices.Contains` и др. Аналогичный пакет `maps` (`Clone`, `Equal`, `DeleteFunc`); итераторы `maps.Keys`/`maps.Values` добавлены в Go 1.23.

## 4.3. Отображения (Maps — Хеш-таблицы)

`map[KeyType]ValueType` — неупорядоченная коллекция пар «ключ — значение» со средним временем поиска $O(1)$.

### Ключевые правила
* **Требование к ключу**: Тип ключа обязан поддерживать оператор сравнения `==` (числа, строки, булевы, указатели, структуры из сравниваемых полей). Срезы, мапы и функции не могут быть ключами.
* **Запрет на взятие адреса**: В Go **запрещено** брать адрес элемента мапы `&m["key"]`, так как при росте таблицы элементы перемещаются в памяти.
* **Случайный порядок обхода**: Итерация `for k, v := range m` специально возвращает элементы в случайном порядке. Для сортировки ключи предварительно извлекают в срез и сортируют через `sort.Strings()`.

```go
// Создание:
ages := make(map[string]int)
ages["alice"] = 25

// Чтение и удаление:
val, ok := ages["bob"] // ok == false, если ключ отсутствует
delete(ages, "alice")  // безопасно даже для несуществующих ключей
```

> [!CAUTION]
> **Опасность `nil map`**:  
> Чтение из `var m map[string]int` (где `m == nil`) безопасно и вернет нулевое значение. Но **любая попытка записи в `nil map` вызовет панику (`panic`)**! Всегда инициализируйте мапу через `make` или литерал `{}`.

### Реализация множеств (Set)
```go
seen := make(map[string]struct{})
seen["item"] = struct{}{} // struct{} не занимает памяти (0 байт)

if _, ok := seen["item"]; ok {
    // элемент присутствует
}
```

## 4.4. Структуры (Structs) и композиция

Структура объединяет разнородные поля в один непрерывный блок памяти:

```go
type Employee struct {
    ID        int
    Name      string
    Salary    int
    ManagerID int
}

p := &Employee{ID: 1, Name: "Иван"}
fmt.Println(p.Name) // автоматическое разыменование указателя (вместо (*p).Name)
```

### Встраивание структур (Embedding) вместо наследования
В Go нет классов и наследования. Повторное использование кода строится на **композиции через анонимные поля**:

```go
type Point struct {
    X, Y int
}

type Circle struct {
    Point  // анонимное поле (встраивание)
    Radius int
}

type Wheel struct {
    Circle // встраивание Circle, содержащей Point
    Spokes int
}
```

* **Продвижение полей (Promotion)**: Поля встроенного типа доступны напрямую:
  ```go
  var w Wheel
  w.X = 10     // эквивалентно w.Circle.Point.X = 10
  w.Radius = 5 // эквивалентно w.Circle.Radius = 5
  ```

## 4.5. Сериализация JSON

Стандартный пакет `encoding/json` выполняет сериализацию структур Go в JSON (маршалинг) и обратно (демаршалинг).

```go
type Movie struct {
    Title  string   `json:"title"`           // имя поля в JSON
    Year   int      `json:"released"`
    Color  bool     `json:"color,omitempty"` // пропуск поля при пустом/нулевом значении
    Actors []string `json:"actors"`
    Secret string   `json:"-"`               // полное исключение поля из JSON
}
```

### Правила работы с JSON:
* **Только экспортируемые поля**: Поля со строчной буквы игнорируются сериализатором.
* **Маршалинг (Go $\to$ JSON)**:
  `data, err := json.Marshal(movie)` или `json.MarshalIndent(movie, "", "  ")`.
* **Демаршалинг (JSON $\to$ Go)**:
  `err := json.Unmarshal(data, &targetStruct)` (всегда передается указатель).
* **Потоковая обработка**:
  `json.NewDecoder(r).Decode(&v)` и `json.NewEncoder(w).Encode(v)` для прямого чтения/записи в поток без буферизации всего документа в память.

> [!NOTE]
> **Актуальность:** опция тега `omitempty` не умеет пропускать нулевые структуры (например, `time.Time{}`). С Go 1.24 есть `json:"...,omitzero"` — пропуск по нулевому значению типа поля. Кроме того, с Go 1.25 доступен экспериментальный новый движок (`GOEXPERIMENT=jsonv2`, пакет `encoding/json/v2`) — API классической версии сохраняется.

## 4.6. Текстовые и HTML-шаблоны (`template`)

Пакеты `text/template` и `html/template` используются для подстановки данных в шаблоны:

* `{{.}}` — текущий элемент контекста.
* `{{.Field}}` — обращение к полю структуры или ключу мапы.
* `{{range .Items}} ... {{end}}` — итерация по коллекции.
* `{{if .Condition}} ... {{else}} ... {{end}}` — условные ветвления.
* `{{.Title | printf "%.30s"}}` — пайплайн обработки данных.

> [!NOTE]
> **Автоэкранирование в `html/template`**:  
> Пакет `html/template` контекстно экранирует спецсимволы (`<`, `>`, `&`, `"`) в HTML, JS, CSS и URL для защиты от XSS-уязвимостей. Для вывода доверенного сырого HTML используйте тип `template.HTML`.
