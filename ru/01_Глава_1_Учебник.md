## 1.1. Hello, World: структура программы и запуск

Минимальная исполняемая программа на Go:

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello, мир!")
}
```

### Ключевые правила
* **Точка входа**: Исполняемая программа всегда объявляется в пакете `package main` и содержит функцию `func main()`. Любой другой пакет компилятор сочтет библиотекой.
* **Строгость компилятора**: Неиспользуемые импорты и объявленные, но неиспользуемые переменные вызывают ошибку компиляции.
* **Точки с запятой `;`**: Вставляются компилятором автоматически в конце строк. Поэтому открывающая фигурная скобка `{` **всегда обязана быть на той же строке**:
  ```go
  func main() { // Корректно
  }

  func main()   // Ошибка компиляции: компилятор вставит ';' после main()
  {
  }
  ```
* **Форматирование кода**: Весь Go-код форматируется единой утилитой `gofmt` (или `goimports`). В экосистеме Go нет споров о стиле отступов и пробелов.

### Команды CLI:
* `go run main.go` — компиляция во временный каталог (с кешем сборки) и немедленный запуск бинарника.
* `go build main.go` — компиляция готового исполняемого бинарного файла без внешних зависимостей.

> [!NOTE]
> **Актуальность:** книга издана в 2015 г. (Go 1.5) — до эпохи модулей. Современный рабочий процесс: один раз выполнить `go mod init <имя-модуля>` в корне проекта, после чего `go run` / `go build` работают как описано. Механика `GOPATH` из старых руководств больше не используется.

## 1.2. Аргументы командной строки и циклы

### Чтение аргументов (`os.Args`)
`os.Args` — срез строк (`[]string`) с аргументами вызова программы:
* `os.Args[0]` — имя/путь исполняемого файла.
* `os.Args[1:]` — срез только переданных аргументов.

### Единственный цикл в Go — `for`
В языке Go нет ключевых слов `while` или `do-while`. Все виды циклов строятся на `for`:

```go
// 1. Классический цикл с тремя компонентами
for i := 1; i < len(os.Args); i++ {
    fmt.Println(os.Args[i])
}

// 2. Аналог while (только условие)
for condition {
    // тело цикла
}

// 3. Бесконечный цикл
for {
    // выход через break или return
}

// 4. Итерация по коллекции (range)
for idx, val := range os.Args[1:] {
    fmt.Printf("%d: %s\n", idx, val)
}
```

### Пустой идентификатор `_` (Blank Identifier)
Если индекс или значение в цикле `range` не нужны, их заменяют на `_`, чтобы компилятор не ругался на неиспользуемую переменную:
```go
for _, arg := range os.Args[1:] {
    fmt.Println(arg)
}
```

> [!TIP]
> **Производительность конкатенации строк**: Сложение строк через `s += " "` внутри цикла неэффективно ($O(n^2)$), так как строки в Go неизменяемы и каждый раз выделяется новый блок памяти.  
> Для склейки используйте `strings.Join(os.Args[1:], " ")` или `bytes.Buffer` / `strings.Builder`.

> [!NOTE]
> **Актуальность (Go 1.22+):**
> * Появилась итерация по целым числам: `for i := range 10` заменяет `for i := 0; i < 10; i++`.
> * Переменная цикла теперь создаётся заново на каждой итерации (в модуле с директивой `go 1.22` и выше). Раньше все итерации делили одну переменную — источник классической ошибки при захвате в замыкании (см. главу 5).

## 1.3. Поиск дубликатов: файлы, потоки и структуры `map`

### Хэш-таблицы (`map`)
* Создание: `counts := make(map[string]int)`
* **Нулевое значение по умолчанию**: Если ключа ещё нет в мапе, при чтении возвращается нулевое значение типа (`0` для чисел, `""` для строк, `false` для bool). Поэтому можно сразу выполнять инкремент:
  ```go
  counts[line]++ // безопасно для новых ключей
  ```
* Итерация `for key, val := range counts` выполняется в **случайном порядке** (рандомизация защищает от скрытой зависимости кода от порядка ключей).

### Потоковое чтение строк (`bufio.Scanner`)
Позволяет читать входные данные любого объема строка за строкой без риска исчерпания памяти:

```go
scanner := bufio.NewScanner(os.Stdin) // или файл, открытый через os.Open()
for scanner.Scan() {
    line := scanner.Text()
    counts[line]++
}
if err := scanner.Err(); err != nil {
    fmt.Fprintf(os.Stderr, "Ошибка чтения: %v\n", err)
}
```

### Чтение небольших файлов целиком
* `os.ReadFile("file.txt")` возвращает пару `([]byte, error)` — считывает весь файл в срез байтов `[]byte`. Его можно разбить на строки через `strings.Split(string(data), "\n")`.

> [!NOTE]
> В Go нет механизма исключений (`try / catch / throw`). Функции возвращают ошибки явным значением `(Result, error)`, которое вызывающий код сразу проверяет: `if err != nil { ... }`.

> [!NOTE]
> **Актуальность (Go 1.16+):** пакет `io/ioutil` объявлен устаревшим. В книге используются `ioutil.ReadFile`, `ioutil.ReadAll`, `ioutil.Discard` — сегодня им соответствуют `os.ReadFile`, `io.ReadAll`, `io.Discard` (конспект уже использует новые варианты).

## 1.4. Рисование и интерфейс `io.Writer`

Пример генерации GIF-анимации фигур Лиссажу демонстрирует универсальность интерфейсов ввода-вывода в Go:

```go
func lissajous(out io.Writer) {
    // генерация кадров и запись в поток
    gif.EncodeAll(out, &anim)
}
```

* Интерфейс `io.Writer` абстрагирует вывод: функции `lissajous` не важно, куда направляются байты — в файл на диске (`*os.File`), в стандартный вывод (`os.Stdout`) или в тело HTTP-ответа (`http.ResponseWriter`).

## 1.5. HTTP-клиент: получение данных по сети

Базовый HTTP GET-запрос средствами стандартного пакета `net/http`:

```go
resp, err := http.Get("https://example.com")
if err != nil {
    log.Fatalf("Ошибка запроса: %v", err)
}
defer resp.Body.Close() // КРИТИЧНО: гарантированно освобождает сокет соединения

// Эффективный потоковый вывод без лишней аллокации в память:
_, err = io.Copy(os.Stdout, resp.Body)
```

> [!IMPORTANT]
> Всегда закрывайте `resp.Body.Close()`. Если тело ответа не закрыто, сетевой сокет утечет и не вернется в пул соединений.

## 1.6. Параллельные HTTP-запросы: горутины и каналы

Go изначально спроектирован для высококонкурентных сетевых сервисов.

```go
func fetch(url string, ch chan<- string) {
    start := time.Now()
    resp, err := http.Get(url)
    if err != nil {
        ch <- fmt.Sprint(err) // отправка ошибки в канал
        return
    }
    nbytes, _ := io.Copy(io.Discard, resp.Body)
    resp.Body.Close()
    secs := time.Since(start).Seconds()
    ch <- fmt.Sprintf("%.2fs  %7d  %s", secs, nbytes, url)
}

func main() {
    ch := make(chan string)
    for _, url := range os.Args[1:] {
        go fetch(url, ch) // параллельный запуск каждой выборки
    }
    for range os.Args[1:] {
        fmt.Println(<-ch) // последовательное чтение результатов
    }
}
```

### Принципы работы
1. **Горутина (`go f()`)**: Легковесный поток рантайма Go. Запуск занимает доли микросекунды и требует всего ~2 КБ памяти.
2. **Канал (`chan`)**: Канал безопасной передачи данных между горутинами.
   * `ch <- val` — отправка значения (блокируется, пока значение не примут).
   * `val := <-ch` — прием значения (блокируется в ожидании поступления данных).
3. **Безопасная синхронизация**: Вместо конкурентного вывода в `stdout` из разных горутин, данные пересылаются в главный поток через канал.

> [!NOTE]
> **Актуальность:** оценка «~2 КБ» по-прежнему верна как минимум для стека горутины; начиная с Go 1.19 начальный размер выделяется адаптивно — на основе исторического среднего использования стеков в приложении.

## 1.7. Создание веб-сервера и защита от гонок

Каждый входящий HTTP-запрос в стандартном `http.Server` обрабатывается **в отдельной горутине**.

```go
var (
    mu    sync.Mutex
    count int
)

func main() {
    http.HandleFunc("/", handler)
    http.HandleFunc("/count", counter)
    log.Fatal(http.ListenAndServe("localhost:8000", nil))
}

func handler(w http.ResponseWriter, r *http.Request) {
    mu.Lock()
    count++
    mu.Unlock()
    fmt.Fprintf(w, "URL.Path = %q\n", r.URL.Path)
}

func counter(w http.ResponseWriter, r *http.Request) {
    mu.Lock()
    fmt.Fprintf(w, "Количество запросов: %d\n", count)
    mu.Unlock()
}
```

> [!WARNING]
> Так как обработчики выполняются параллельно, одновременный доступ к разделяемой переменной `count++` без мьютекса приведет к состоянию гонки данных (**Data Race**). Для защиты критической секции используется `sync.Mutex`.

## 1.8. Синтаксические особенности и конструкции

* **`switch` без проваливания**:
  В Go не нужен `break` в каждом `case`. Чтобы принудительно продолжить выполнение следующей ветки, используется `fallthrough`.
  ```go
  switch {
  case x > 0:
      return +1
  case x < 0:
      return -1
  default:
      return 0
  }
  ```
* **Инициализация в `if`**:
  Область видимости служебных переменных можно ограничить блоком `if`:
  ```go
  if err := r.ParseForm(); err != nil {
      log.Println(err)
  }
  ```
* **Указатели (`&` и `*`)**:
  `&x` возвращает адрес переменной, `*p` разыменовывает значение. В Go **нет адресной арифметики** (нельзя делать `p++`), что обеспечивает безопасность памяти. Единственное исключение — низкоуровневые преобразования `unsafe.Pointer` (см. главу 13).
