## 7.1. Интерфейсы как контракты поведения

В Go существует принципиальная разница между конкретными и абстрактными типами:
* **Конкретный тип** (`int`, `*os.File`, `*bytes.Buffer`) — определяет физическую структуру данных в памяти и методы для работы с ней.
* **Интерфейс (Абстрактный тип)** — полностью скрывает данные и описывает исключительно **поведение** через контракт методов.

```go
type Stringer interface {
    String() string
}
```

*Любой тип с методом `String() string` автоматически удовлетворяет интерфейсу `fmt.Stringer` и корректно форматируется в `fmt.Printf("%v", x)`.*

### Соглашения об именовании

Однометодные интерфейсы именуются с суффиксом `-er` (`Reader`, `Writer`, `Closer`, `Formatter`).

### Композиция интерфейсов (Embedding)

Интерфейсы можно объединять в более крупные контракты:

```go
type Reader interface { Read(p []byte) (n int, err error) }
type Writer interface { Write(p []byte) (n int, err error) }

type ReadWriter interface {
    Reader
    Writer
}
```

## 7.2. Неявная реализация (Implicit Implementation)

В Go **нет ключевого слова `implements`**. Тип удовлетворяет интерфейсу автоматически, если реализует все заявленные методы.

```go
var w io.Writer
w = os.Stdout         // OK: *os.File реализует метод Write
w = new(bytes.Buffer) // OK: *bytes.Buffer реализует метод Write
```

### Нюанс `T` vs `*T`:

Если метод объявлен для получателя-указателя `func (s *IntSet) String() string`, то интерфейс `fmt.Stringer` реализует **только `*IntSet`**, но не само значение `IntSet`.

### Пустой интерфейс `any` (`interface{}`)

Не содержит методов вообще $\to$ **ему удовлетворяет значение абсолютно любого типа** (`any` — официальный псевдоним `interface{}` начиная с Go 1.18; в книге используется только старая запись):

```go
var x any = 42
x = "текст"
x = []int{1, 2, 3}
```

> [!TIP]
> **Статическая проверка реализации во время компиляции**:
> ```go
> var _ io.Writer = (*MyType)(nil) // ошибка компиляции, если MyType не реализует io.Writer
> ```

## 7.3. Внутреннее устройство значений интерфейсов

Концептуально значение любого интерфейса состоит из двух компонентов:
1. **Динамический тип (Type Descriptor)** — информация о конкретном типе (`*bytes.Buffer`, `int`).
2. **Динамическое значение (Value Pointer)** — указатель на сами данные в памяти.

```text
Интерфейс: [ Динамический тип (*os.File) | Динамическое значение (&os.Stdout) ]
```

> [!CAUTION]
> **Опасность: `nil`-указатель внутри интерфейса не равен `nil`!**  
> Значение интерфейса равно `nil` **только тогда, когда и тип, и значение равны `nil`**. Если интерфейс содержит тип и `nil`-указатель, проверка `if iface != nil` вернет `true`:
>
> ```go
> func test(out io.Writer) {
>     // out НЕ равен nil! out = (*bytes.Buffer, nil)
>     if out != nil {
>         out.Write([]byte("data")) // ПАНИКА! Вызов метода на nil-указателе
>     }
> }
>
> var buf *bytes.Buffer // buf == nil
> test(buf)             // передача ТИПИЗИРОВАННОГО nil: интерфейс получит (*bytes.Buffer, nil)
> ```
>
> **Правильно**: объявлять переменную сразу типом интерфейса `var buf io.Writer` (тогда интерфейс будет хранить `(nil, nil)` и проверка сработает).

## 7.4. Сортировка (`sort.Interface`) и веб-обработчики (`http.Handler`)

### Сортировка через `sort.Interface`

Пакет `sort` абстрагирован от конкретных структур данных через 3 метода:

```go
type Interface interface {
    Len() int           // длина
    Less(i, j int) bool // элемент i меньше j?
    Swap(i, j int)      // обмен i и j
}

type ByAge []Person
func (a ByAge) Len() int           { return len(a) }
func (a ByAge) Less(i, j int) bool { return a[i].Age < a[j].Age }
func (a ByAge) Swap(i, j int)      { a[i], a[j] = a[j], a[i] }

sort.Sort(ByAge(people))
```

> [!NOTE]
> **Актуальность:** после выхода книги появились более короткие способы: `sort.Slice(people, func(i, j int) bool { return people[i].Age < people[j].Age })` (Go 1.8), а с Go 1.21 — дженерик-функции `slices.Sort`, `slices.SortFunc(people, func(a, b Person) int { return cmp.Compare(a.Age, b.Age) })` и стабильная `slices.SortStableFunc`. Свой тип с 3 методами (`sort.Interface`) нужен лишь для сложных структур данных.

### Веб-обработчики (`http.Handler`)

```go
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

// Адаптер http.HandlerFunc превращает обычную функцию func(w, r) в Handler:
mux.Handle("/list", http.HandlerFunc(myHandler))
```

## 7.5. Утверждения типов (Type Assertions)

Операция `x.(T)` проверяет динамический тип интерфейса `x`:

```go
var w io.Writer = os.Stdout

// 1. Утверждение конкретного типа:
f := w.(*os.File) // f имеет тип *os.File

// 2. Безопасная форма с comma-ok:
if f, ok := w.(*os.File); ok {
    // работа с f
}

// 3. Утверждение другого интерфейса (запрос поведения):
if rw, ok := w.(io.ReadWriter); ok {
    // объект поддерживает и чтение, и запись
}
```

## 7.6. Переключатель типов (Type Switch)

Специальная форма `switch` для сопоставления с типами:

```go
func sqlQuote(x any) string {
    switch x := x.(type) {
    case nil:
        return "NULL"
    case int, int64:
        return fmt.Sprintf("%d", x)
    case bool:
        if x {
            return "TRUE"
        }
        return "FALSE"
    case string:
        return fmt.Sprintf("'%s'", strings.ReplaceAll(x, "'", "''"))
    default:
        panic(fmt.Sprintf("неподдерживаемый тип: %T", x))
    }
}
```

## 7.7. Советы по проектированию интерфейсов

> [!TIP]
> 1. **Не создавайте интерфейсы заранее**: объявляйте интерфейс только тогда, когда у вас есть как минимум 2 разных типа, требующих единого контракта.
> 2. **Маленькие интерфейсы — самые мощные**: интерфейсы с 1–2 методами (`io.Reader`, `io.Writer`, `fmt.Stringer`) максимально гибки и переиспользуемы.
> 3. **Золотое правило Go**: *«Принимайте интерфейсы, возвращайте структуры»* (требуйте минимум необходимого поведения на входе функции).
