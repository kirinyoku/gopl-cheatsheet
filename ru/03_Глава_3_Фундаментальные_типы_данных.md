## 3.1. Целые числа (Integers)

### Классификация целочисленных типов

| Тип | Размер | Диапазон / Назначение |
| :--- | :--- | :--- |
| `int8` / `uint8` | 1 байт | от -128 до 127 / от 0 до 255 |
| `int16` / `uint16` | 2 байта | от -32 768 до 32 767 / от 0 до 65 535 |
| `int32` / `uint32` | 4 байта | ~2 миллиарда |
| `int64` / `uint64` | 8 байтов | Большие числа (~$9 \times 10^{18}$) |
| **`int` / `uint`** | 1 слово (4 или 8 байт) | Зависит от архитектуры (32/64-бит). **Основной рабочий тип**. |
| **`byte`** | 1 байт | Синоним `uint8` для сырых байтов данных |
| **`rune`** | 4 байта | Синоним `int32` для кодовых точек Unicode |
| **`uintptr`** | 1 слово | Беззнаковое число для адресов в `unsafe` |

> [!NOTE]
> `int` и `int64` (или `int32`) — это **разные типы для компилятора**, даже если на 64-битной машине они имеют одинаковый размер. Автоматического неявного приведения нет.

### Побитовые операции
* `&` (AND), `|` (OR), `^` (XOR, а в унарном виде `^x` — NOT).
* `&^` — **сброс бита (AND NOT)**: `z = x &^ y` (обнуляет в `x` те биты, которые установлены в `y`).
* `<<` и `>>` — сдвиги (в книге счётчик обязан быть беззнаковым `uint`; начиная с Go 1.13 допустимо любое целое, но отрицательное значение вызывает панику при исполнении, а константное — ошибку компиляции).

> [!TIP]
> **Почему `len()` возвращает знаковый `int`, а не беззнаковый `uint`**:  
> Беззнаковый счетчик в циклах с обратным отсчетом приводит к выходу в бесконечный цикл при переполнении через 0 (`0 - 1 == 18446744073709551615`):
> ```go
> // Безопасно, так как i знаковый int и при i < 0 цикл штатно завершится:
> for i := len(slice) - 1; i >= 0; i-- {
>     // ...
> }
> ```
> *Правило Go*: беззнаковые типы `uint` используют для битовых масок, хеширования и криптографии, а для обычной арифметики и счетчиков — `int`.

## 3.2. Числа с плавающей точкой (Floats)

Два стандартных вещественных типа (IEEE 754):
* `float32` — ~6 десятичных цифр точности.
* `float64` — ~15 десятичных цифр точности (**стандарт по умолчанию**).

### Специальные значения и ловушка `NaN`
* `+Inf` и `-Inf` — положительная и отрицательная бесконечность.
* `NaN` (Not a Number) — результат неопределенности (`0.0 / 0.0`, `math.Sqrt(-1)`).

> [!CAUTION]
> **Любое сравнение с `NaN` всегда возвращает `false`** (единственное исключение — `!=`, который наоборот всегда `true`).
> ```go
> nan := math.NaN()
> fmt.Println(nan == nan) // false
> fmt.Println(nan != nan) // true
> ```
> Для проверки на `NaN` используйте специальную функцию: `math.IsNaN(x)`.

## 3.3. Комплексные числа и булевы типы

* **Комплексные числа**: `complex64` (два `float32`) и `complex128` (два `float64`). Литерал: `z := 1 + 2i`. Функции: `real(z)`, `imag(z)`.
* **Булев тип (`bool`)**: Принимает только `true` или `false`.
* **Ленивые вычисления**: В цепочке `A && B` выражение `B` не вычисляется, если `A == false`. Это позволяет безопасно писать проверки вроде `if s != "" && s[0] == 'x'`.
* В Go **нет неявного приведения чисел или указателей к bool** (нельзя писать `if 1 { ... }` или `if ptr { ... }`).

## 3.4. Строки, кодировка UTF-8 и руны (`rune`)

### Внутреннее устройство строк
* Строка в Go — это **неизменяемая последовательность байтов**.
* `len(s)` возвращает **количество байт**, а не букв.
* Индексация `s[i]` обращается к отдельному $i$-му байту.
* Срезы подстрок `s[a:b]` работают мгновенно ($O(1)$), так как не копируют память, а создают легковесный заголовок на тот же массив байтов.

```go
// Обычная строка с экранированием:
s := "Привет\n"

// "Сырая" (Raw) строка в обратных кавычках (без обработки экранирования):
raw := `SELECT id, name
        FROM users
        WHERE email = "test@example.com"`
```

### Разница между `byte`, `rune` и `string`
* **UTF-8** — кодировка переменной длины (ASCII — 1 байт, кириллица — 2 байта, эмодзи — 4 байта).
* **Руна (`rune`)** — числовой код символа в таблице Unicode (тип `int32`), записывается в одинарных кавычках: `'A'`, `'я'`, `'🚀'`.

```go
s := "Привет"
fmt.Println(len(s))                    // 12 (байт)
fmt.Println(utf8.RuneCountInString(s)) // 6 (символов)

// Цикл for-range автоматически декодирует UTF-8 посимвольно:
for byteOffset, r := range s {
    fmt.Printf("байт: %d, руна: %c\n", byteOffset, r)
}
```

> [!WARNING]
> Преобразование `string(65)` вернет символ с Unicode-кодом 65, т.е. `"A"`, а **не** строку `"65"`.  
> Для конвертации чисел в текст используйте пакет `strconv`.

## 3.5. Пакеты для работы со строками

* **`strings`**: `Contains`, `HasPrefix`, `Join`, `Split`, `Replace`, `ToLower`, `TrimSpace`.
* **`bytes`**: Аналогичные функции для срезов байт `[]byte` без лишних аллокаций памяти.
* **`bytes.Buffer` / `strings.Builder`**: Накопление строк без создания сотен промежуточных объектов:
  ```go
  var buf bytes.Buffer
  buf.WriteString("Привет, ")
  buf.WriteString("Go!")
  result := buf.String()
  ```
* **`strconv`**: Преобразование строк в числа и обратно:
  * Число $\to$ Текст: `strconv.Itoa(123)` или `fmt.Sprintf("%d", 123)`
  * Текст $\to$ Число: `x, err := strconv.Atoi("123")` или `strconv.ParseFloat("3.14", 64)`

> [!NOTE]
> **Актуальность:** `strings.Builder` появился в Go 1.10 — уже после издания книги. Для накопления чисто строковых данных он сегодня предпочтительнее `bytes.Buffer`: не делает лишнюю копию при финальном `.String()` и пресекает копирование самого себя.

## 3.6. Константы, генератор `iota` и нетипизированные константы

Константы (`const`) вычисляются строго во время компиляции.

### Генератор констант `iota`
Автоматически инкрементирует значение с `0` в блоке `const`:

```go
// 1. Простое перечисление (Enum)
type Weekday int
const (
    Sunday Weekday = iota // 0
    Monday                // 1
    Tuesday               // 2
    Wednesday             // 3
)

// 2. Битовые маски (степени двойки)
type Flags uint
const (
    FlagUp   Flags = 1 << iota // 1 (0001)
    FlagBroadcast              // 2 (0010)
    FlagLoopback               // 4 (0100)
)

// 3. Размеры данных
const (
    _   = 1 << (10 * iota) // пропуск iota == 0
    KiB                    // 1024
    MiB                    // 1048576
    GiB                    // 1073741824
)
```

### Нетипизированные константы
Литералы вроде `42`, `3.14` или `math.Pi` изначально не имеют жесткого типа и вычисляются компилятором с высокой точностью (256+ бит), автоматически принимая нужный тип в контексте присваивания:

```go
var a float32 = math.Pi // примет float32
var b float64 = math.Pi // примет float64
```

> [!NOTE]
> Будьте внимательны с целочисленным делением в константах:
> * `5 / 9 * (f - 32)` $\to$ `0` (так как `5 / 9` как целочисленная операция дает `0`).
> * `5.0 / 9.0 * (f - 32)` $\to$ корректное вещественное вычисление.

> [!NOTE]
> **Актуальность (Go 1.13+):** числовые литералы расширены — в книге их нет:
> * Префиксы: двоичный `0b1010`, восьмеричный `0o755` (старая форма с ведущим нулём `0755` тоже работает), шестнадцатеричный `0xFF`.
> * Разделители разрядов: `1_000_000`, `0x4B_CC`.
> * Шестнадцатеричные дроби с двоичной экспонентой: `0x1p-2` (= `0.25`).
