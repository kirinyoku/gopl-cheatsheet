## 12.1. Зачем нужна рефлексия

Рефлексия позволяет программе **исследовать типы, структуру и значения переменных во время выполнения**, а также динамически изменять их без знания точных типов на этапе компиляции.

### Практическое применение:

* Универсальная сериализация и десериализация (`encoding/json`, `encoding/xml`, S-выражения).
* Универсальное форматирование произвольных значений (`fmt.Printf("%v", x)`).
* Шаблонизаторы (`text/template`, `html/template`).
* Автоматическая распаковка параметров HTTP-запросов в поля структур.

> [!NOTE]
> Конструкция `switch x.(type)` не способна заменить рефлексию, так как невозможно статически перечислить бесконечное множество типов срезов, мап и структур.

> [!NOTE]
> **Актуальность (Go 1.18+):** часть задач, ранее требовавших рефлексии, теперь решается дженериками — с сохранением статических типов и без накладных расходов (пакеты `slices`, `maps`, собственные обобщённые функции). Рефлексия незаменима там, где набор типов известен только в рантайме: сериализация по тегам, ORM, плагины.

## 12.2. Фундаментальные типы: `reflect.Type` и `reflect.Value`

```go
import "reflect"

t := reflect.TypeOf(3)    // reflect.Type (динамический тип, "int")
v := reflect.ValueOf(3)   // reflect.Value (динамическое значение, 3)

t2 := v.Type()            // получение reflect.Type из reflect.Value
x := v.Interface().(int)  // распаковка: reflect.Value -> any -> int
```

### Разница между `Type` и `Kind`:

* **`Type`** описывает точный тип (`time.Duration`, `*os.File`, `main.Movie`).
* **`Kind`** описывает базовую категорию типа (`reflect.Int64`, `reflect.Ptr`, `reflect.Struct`, `reflect.Slice`, `reflect.Map`, `reflect.Interface`, `reflect.Invalid`).

```go
var d time.Duration = 1 * time.Second
v := reflect.ValueOf(d)

fmt.Println(v.Type()) // "time.Duration"
fmt.Println(v.Kind()) // reflect.Int64
```

## 12.3. Навигация по составным структурам данных

Методы `reflect.Value` для рекурсивного обхода:

| Категория (`Kind`) | Методы в `reflect.Value` |
| :--- | :--- |
| **`Slice`, `Array`** | `v.Len()`, `v.Index(i)` (получение $i$-го элемента) |
| **`Struct`** | `v.NumField()`, `v.Field(i)`, `v.Type().Field(i).Name` |
| **`Map`** | `v.MapKeys()`, `v.MapIndex(key)`, `v.SetMapIndex(key, val)` |
| **`Ptr`, `Interface`** | `v.IsNil()`, `v.Elem()` (разыменование / извлечение значения) |

> [!WARNING]
> При рекурсивном обходе графов объектов (например, циклических списков) рефлексия без отслеживания посещенных адресов уйдет в **бесконечную рекурсию**.

## 12.4. Установка и изменение переменных через `reflect.Value`

Чтобы изменить переменную через рефлексию, она должна быть **адресуемой (Addressable)** и **устанавливаемой (Settable)**:

```go
x := 2

// НЕПРАВИЛЬНО: передано значение по копии
v := reflect.ValueOf(x)
// v.CanAddr() == false -> v.SetInt(3) вызовет ПАНИКУ!

// ПРАВИЛЬНО: передаем указатель и берем Elem()
v = reflect.ValueOf(&x).Elem()
fmt.Println(v.CanAddr()) // true
fmt.Println(v.CanSet())  // true

v.SetInt(3) // изменяет x на 3
fmt.Println(x) // 3
```

> [!CAUTION]
> **Ограничение доступа к неэкспортированным полям**:  
> Рефлексия умеет **читать** неэкспортированные поля структур, но попытка **записать** в них (`v.Field(i).Set(...)`) вызовет **панику (`panic`)**. Для приватных полей `v.CanSet()` всегда возвращает `false`.

## 12.5. Доступ к тегам полей структур (Struct Field Tags)

```go
type SearchParams struct {
    Query      string `http:"q"`
    MaxResults int    `http:"max"`
    Exact      bool   `http:"x"`
}

func Unpack(req *http.Request, ptr any) error {
    v := reflect.ValueOf(ptr).Elem() // структура под указателем
    for i := 0; i < v.NumField(); i++ {
        fieldInfo := v.Type().Field(i)   // reflect.StructField
        tag := fieldInfo.Tag.Get("http") // парсинг значения ключа тега

        if val := req.FormValue(tag); val != "" {
            // парсинг строки val и вызов v.Field(i).SetString/SetInt/...
        }
    }
    return nil
}
```

* Помимо `Tag.Get(name)` есть `Tag.Lookup(name) (value string, ok bool)` (добавлен в Go 1.7) — позволяет отличить пустой тег от отсутствующего.

## 12.6. Инспекция методов типа

Рефлексия позволяет перечислить все методы типа и динамически вызвать их:

```go
t := reflect.TypeOf(time.Hour)
for i := 0; i < t.NumMethod(); i++ {
    m := t.Method(i)
    fmt.Printf("Метод: %s, Сигнатура: %s\n", m.Name, m.Type)
}
```

## 12.7. Предостережения: Риски и цена рефлексии

> *«Рефлексия — мощный инструмент, но использовать ее следует осторожно и умеренно».*

### 3 главных недостатка:

1. **Хрупкость (Fragility)**: Ошибки несоответствия типов не проверяются компилятором и приводят к `panic` во время исполнения.
2. **Ухудшение читаемости и поддержки**: Рефлексивный код сложен для понимания, а инструменты статического анализа и авторефакторинга IDE не могут отслеживать такие связи.
3. **Падение производительности**: Рефлексивные вызовы работают **на 1–2 порядка медленнее** прямого статически типизированного Go-кода. Не используйте рефлексию в высоконагруженных горячих путях.
