## 5.1. Объявления и семантика вызовов

```go
func name(parameterList) (resultList) {
    body
}
```

### Ключевые особенности
* **Сигнатура (Тип функции)**: Определяется только типами параметров и возвращаемых значений (например, `func(int, int) bool`). Имена параметров не влияют на тип функции.
* **Отсутствие значений по умолчанию**: В Go **нет параметров по умолчанию** и **нет вызовов по именам аргументов** (`f(x=1)`). Все параметры передаются явно и позиционно.
* **Строгая передача по значению (Pass by Value)**: Функция всегда получает **копию** аргумента.
  * Для ссылочных типов (указатели `*T`, срезы `[]T`, мапы `map`, каналы `chan`, функции `func`) копируется сам легковесный дескриптор, поэтому функция может изменять нижележащие данные.

## 5.2. Рекурсия и динамический стек

* Функции в Go могут рекурсивно вызывать сами себя, что удобно для обхода древовидных структур (HTML-документов, AST, графов).
* **Динамический стек вызовов**:
  * В большинстве языков (C, C++, Java) стек вызовов жестко ограничен (обычно сотни килобайт — единицы мегабайт), из-за чего глубокая рекурсия приводит к `Stack Overflow`.
  * В Go стек горутины начинается с минимального размера (~2 КБ) и **динамически растет** — до предела, настраиваемого `debug.SetMaxStack` (~1 ГБ по умолчанию на 64-битных системах). Глубокая рекурсия в Go практически безопасна.

## 5.3. Множественные возвращаемые значения

Функции могут возвращать несколько значений (стандартная идиома: результат и ошибка):

```go
func findLinks(url string) ([]string, error) {
    resp, err := http.Get(url)
    if err != nil {
        return nil, err
    }
    defer resp.Body.Close()
    var links []string
    // ... разбор resp.Body и наполнение links ...
    return links, nil
}
```

### Именованные результаты и «пустой возврат» (Bare Return)
Возвращаемые значения можно именовать прямо в сигнатуре. Они инициализируются нулевыми значениями:

```go
func Count(url string) (words, images int, err error) {
    // words = 0, images = 0, err = nil
    words = 10
    images = 2
    return // пустой возврат: эквивалентен return words, images, err
}
```

> [!TIP]
> Именование возвращаемых значений полезно как документация API. Однако избегайте «пустого возврата» (`bare return`) в длинных функциях, так как он скрывает возвращаемые значения и ухудшает читаемость.

## 5.4. Стратегии обработки ошибок (`error`)

В Go нет исключений для штатных ошибок. Ошибки — это обычные значения встроенного интерфейсного типа `error` (`nil` — успех, `!= nil` — ошибка).

### 5 стратегий обработки ошибок:
1. **Проброс наверх (Propagation) с контекстом**:
   ```go
   doc, err := html.Parse(resp.Body)
   if err != nil {
       return nil, fmt.Errorf("parsing %s as HTML: %v", url, err)
   }
   ```
   *Сообщения об ошибках пишутся со строчной буквы и без точки на конце*, чтобы цепочка контекстов читалась как единая фраза.
2. **Повторная попытка (Retry with Backoff)**: Для временных сетевых или БД сбоев с экспоненциальной задержкой.
3. **Завершение процесса (Fatal Exit)**: `log.Fatalf(...)` или `os.Exit(1)`. Допустимо **только в пакете `main`** (точке входа). Библиотеки никогда не должны принудительно завершать выполнение программы.
4. **Логирование и продолжение работы**: `log.Printf("non-fatal: %v", err)`.
5. **Осознанное игнорирование**: Только если ошибка заведомо безопасна (например, `os.RemoveAll(tmpDir)`).

### Маркер конца файла `io.EOF`
Для различения нормального завершения потока данных от сетевых/дисковых сбоев используется константа `io.EOF`:

```go
for {
    r, _, err := in.ReadRune()
    if err == io.EOF {
        break // поток закончился штатно
    }
    if err != nil {
        return err // реальная ошибка ввода-вывода
    }
}
```

> [!NOTE]
> **Актуальность (Go 1.13+):** для оборачивания ошибок используйте глагол `%w` — `fmt.Errorf("reading %s: %w", url, err)`. Исходная ошибка сохраняется в цепочке и проверяется через `errors.Is(err, io.EOF)` / `errors.As(err, &target)`, а не прямым сравнением `==` (которое ломается, если ошибка обёрнута).

## 5.5. Анонимные функции и замыкания (Closures)

Функции в Go являются объектами первого класса: их можно присваивать переменным, передавать в аргументы и возвращать из функций.

```go
func squares() func() int {
    var x int
    return func() int {
        x++
        return x * x
    }
}

f := squares()
fmt.Println(f()) // 1
fmt.Println(f()) // 4
fmt.Println(f()) // 9
```
* Анонимная функция образует **замыкание**: она захватывает переменную `x` внешней функции, которая автоматически перемещается в кучу и сохраняет состояние между вызовами.

> [!CAUTION]
> **Особенность захвата переменной цикла в замыканиях**:  
> Все замыкания, созданные в цикле, захватывают **одну и ту же ячейку памяти** переменной цикла!
>
> ```go
> // ОШИБКА: к моменту вызова dir будет равен последнему элементу!
> for _, dir := range dirs {
>     tasks = append(tasks, func() { os.RemoveAll(dir) })
> }
>
> // ПРАВИЛЬНО: локальная копия переменной на каждой итерации
> for _, dir := range dirs {
>     dir := dir // локальная переменная
>     tasks = append(tasks, func() { os.RemoveAll(dir) })
> }
> ```

> [!NOTE]
> **Актуальность (Go 1.22+):** в модуле с директивой `go 1.22` и выше проблема устранена языком — переменная цикла создаётся заново на каждой итерации, поэтому работают корректно **обе** версии кода. Приём `dir := dir` нужен только при чтении/написании кода под старые версии Go.

## 5.6. Вариативные функции (`...`)

Функции с переменным числом аргументов принимают срез значений:

```go
func sum(vals ...int) int {
    total := 0
    for _, val := range vals {
        total += val
    }
    return total
}

sum(1, 2, 3)     // 6
nums := []int{1, 2, 3, 4}
sum(nums...)     // распаковка среза через '...'
```

## 5.7. Отложенные вызовы (`defer`)

Инструкция `defer` гарантирует вызов функции при **любом выходе из окружающей функции** (при `return` или при `panic`):

```go
func ReadFile(filename string) ([]byte, error) {
    f, err := os.Open(filename)
    if err != nil {
        return nil, err
    }
    defer f.Close() // файл гарантированно закроется при любом выходе
    return io.ReadAll(f)
}
```

### Правила работы `defer`:
1. **Порядок LIFO (Стек)**: Несколько отложенных вызовов выполняются в обратном порядке (последний объявленный выполнится первым).
2. **Фиксация аргументов**: Аргументы отложенной функции вычисляются **в момент выполнения строки с `defer`**, а не в момент фактического вызова.
3. **Изменение возвращаемых значений**: Отложенное замыкание может модифицировать именованные возвращаемые переменные перед возвратом вызывающему коду.

> [!WARNING]
> **`defer` внутри бесконечных циклов или циклов по файлам**:  
> Ресурсы, открытые в цикле с `defer f.Close()`, **не закроются до завершения всей функции**, что может привести к исчерпанию файловых дескрипторов.  
> *Решение*: выносите тело цикла в отдельную вспомогательную функцию.

## 5.8. Аварийная ситуация (`panic`) и восстановление (`recover`)

### Паника (`panic`)
* `panic` немедленно останавливает нормальное выполнение, запускает все `defer` в текущей горутине и завершает процесс с дампом стека.
* **Применение**: Только для критических программных багов (выход за границы среза, разыменование `nil`, нарушение инвариантов) или в функциях `Must...` (`regexp.MustCompile`) при инициализации программы. Не используйте `panic` для обычных ошибок ввода-вывода!

### Перехват (`recover`)
`recover()` перехватывает панику, останавливает аварийное завершение и возвращает переданное в `panic` значение:

```go
func Parse(input string) (syntax *Syntax, err error) {
    defer func() {
        if p := recover(); p != nil {
            err = fmt.Errorf("внутренняя паника: %v", p)
        }
    }()
    // код парсера, который может запаниковать
    return parseInternal(input), nil
}
```

> [!IMPORTANT]
> 1. `recover()` работает **только внутри функций, вызванных через `defer`**. В других местах он возвращает `nil`.
> 2. Библиотеки и публичные пакеты **никогда не должны допускать выхода необработанной паники за пределы своего API**: все внутренние паники должны перехватываться и возвращаться через `error`.
